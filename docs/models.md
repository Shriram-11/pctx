# PCTX Models (`src/pctx/models.py`)

[`src/pctx/models.py`](file:///c:/Users/nshri/Github/pctx/src/pctx/models.py) defines the central domain dataclasses used across the entire `pctx` system: `Document` and `Section`.

---

## Why a Dedicated Models Module?

In CLI tools that integrate parsers, database storage, and presentation layers, modules often invent ad-hoc dictionaries or couple themselves directly to database rows.

`models.py` acts as a neutral contract between:
- **Parser** (`parser.py`): Produces instances of `Section` from raw Markdown.
- **Index Engine** (`index.py`): Maps `Document` and `Section` objects to SQLite relational tables and restores them from queries.
- **Render Engine** (`render.py`): Consumes `Document` and `Section` instances to generate formatted text or JSON without querying the database directly.

This decoupling guarantees that the parser has no knowledge of SQLite, and the renderer has no knowledge of file IO or database transactions.

## The `Document` Dataclass

Represents an indexed Markdown file and its metadata.

```python
@dataclass
class Document:
    path: str           # Relative path from index root (e.g. "guide/setup.md")
    root: str           # Absolute path of index root (e.g. "/workspace/docs")
    content_hash: str   # SHA-256 hex digest of the raw file content
    summary: Optional[str] = None  # L0 document-level summary preview
    id: Optional[int] = None       # Primary key generated by SQLite
```

### Field Semantics & Invariants

| Field | Type | Description | Invariants & Rules |
|---|---|---|---|
| `path` | `str` | Relative file path | Normalized with forward slashes (`/`) across all platforms (Windows/Linux/macOS). Must be unique per index root. |
| `root` | `str` | Absolute root directory | Canonicalized absolute directory where `.pctx/` resides. |
| `content_hash` | `str` | SHA-256 content checksum | 64-character lowercase hex string. Re-computed during indexing to detect modified files without comparing timestamps or file sizes. |
| `summary` | `Optional[str]` | L0 document summary | Follows the deterministic fallback order: First H1 text $\to$ first heading $\to$ first paragraph of body text $\to$ document path. |
| `id` | `Optional[int]` | Relational primary key | `None` prior to insertion into SQLite; populated with `cur.lastrowid` once persisted. |

## The `Section` Dataclass

Represents an individual node in the document hierarchy, ranging from the document root (Level 0) down to deeply nested headings (H1–H6).

```python
@dataclass
class Section:
    doc_id: int                    # Foreign key referencing Document.id
    address: str                   # Stable address (e.g. "doc.md#overview/goals")
    heading: Optional[str]         # Raw text of heading (None for L0 root)
    slug: str                      # Sanitized URL-friendly slug
    level: int                     # 0=document, 1=H1, 2=H2, ..., 6=H6
    start_line: int                # 0-based starting line in original source file
    end_line: int                  # 0-based ending line (inclusive) in original source file
    content: str                   # Raw Markdown source slice for this section
    estimated_tokens: int          # Deterministic token count
    parent_id: Optional[int] = None  # Foreign key referencing parent Section.id
    id: Optional[int] = None       # Primary key in SQLite
    children: list = field(default_factory=list) # Optional in-memory tree nodes
```

### Field Semantics & Invariants

| Field | Type | Description | Rules & Constraints |
|---|---|---|---|
| `doc_id` | `int` | Parent document ID | Must reference an existing record in the `documents` table. Enforced by SQLite `ON DELETE CASCADE`. |
| `address` | `str` | Stable section address | Format: `<path>` for Level 0; `<path>#<parent-slug>/<slug>` for Level $\ge 1$. Unique across the entire index. |
| `heading` | `Optional[str]` | Heading title | `None` for Level 0 document sections; string title for headings. Inline formatting is preserved in `heading` but stripped in `slug`. |
| `slug` | `str` | Slug identifier | Lowercased, alphanumeric and hyphens only. Sibling duplicates receive `-2`, `-3` suffixes. |
| `level` | `int` | Hierarchy level | `0` represents the complete document. `1` to `6` correspond to Markdown `#` through `######`. |
| `start_line` | `int` | Start line | 0-based index into original source file lines. |
| `end_line` | `int` | End line | 0-based index into original source file lines (inclusive). |
| `content` | `str` | Source markdown | Exact substring of the source file spanning lines `[start_line, end_line]`. Contains heading markers and all nested subsections. |
| `estimated_tokens` | `int` | Token count | Evaluated as $\max(1, \lfloor \text{bytes} / 4 \rfloor)$ over UTF-8 bytes of `content`. |
| `parent_id` | `Optional[int]` | Parent section ID | `None` for Level 0 sections. For Level $L \ge 1$, points to the closest enclosing section with level $< L$. |
| `id` | `Optional[int]` | Primary key | Populated by SQLite during insertion. |
| `children` | `list[Section]` | In-memory tree list | Used during rendering to represent nested subsections without issuing extra database queries. |

---

## Architectural Guarantees

1. **Self-Contained Content**: Every section's `content` contains its full markdown source text. Retrieving an address does not require stitching lines together at runtime.
2. **Reconstruction Invariant**: For any document, line ranges `[start_line, end_line]` correspond to exact byte slices in the original file on disk.
3. **Database Independence**: The models are pure Python dataclasses with zero reliance on SQLite bindings, allowing them to be constructed, unit-tested, and rendered in memory.
